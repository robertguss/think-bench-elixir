# Phase 4 handoff — Focus and Outline views

Worker: Opus, 2026-09-13. Scope: Phase 4 only. Phase 5 (the AI's habits) not started.

## What was built

### Server: pins

- **`Card.pinned`**, a boolean attribute (`allow_nil? false`, default `false`, public).
  Migration `priv/repo/migrations/20260913041222_phase_4_card_pinned.exs` was generated by
  `mix ash.codegen phase_4_card_pinned` and reviewed. It adds one column with a default.
- **The Graph action is `Card.update`** (`Graph.update_card`). It now accepts `pinned`
  along with title, body, tags and status, so a pin is an ordinary evented update: one
  `update` event with `changes: {pinned: true}` and the acting actor.
- **`update_card` tool** (MCP and channel, same generic action on `Mcp.Board`) takes an
  optional `pinned` boolean. The description tells the model what it does. The
  "pass at least one…" error now lists `pinned`.
- **`Mcp.Json.card`** includes `pinned`, so `read_board`, tool results, the channel join
  and event pushes all carry it.

### UI (`assets/js`)

- **`board/graph.ts`** holds the pure logic, with no React or DOM:
  - `focusTiers(centreId, cards, links)` sorts linked cards into parents, children and
    jumps. `HIERARCHY_TYPES` mirrors `@hierarchy_types` in `Graph.Link`.
    - A hierarchical link out of the centre makes the target a **parent**, labelled
      `type →`.
    - A hierarchical link into the centre makes the source a **child**, labelled
      `← type`.
    - `cites` and unknown types, in either direction, are **jumps**.
    - A card linked twice in one tier shows once with both labels. Self links and
      links to cards not on the board are ignored.
  - `pushTrail(trail, prev, next)` handles the trail.
  - `outlineGroups(cards, links)` builds the Outline groups.
- **`board/CardFace.tsx`**: the Phase 3 card markup pulled out of `MapView`. It has three
  variants:
  - `map`: unchanged.
  - `centre`: 340px, accent ring, full body with line breaks, tags.
  - `neighbour`: 200px, a button showing kind, title, and the link label that placed it.

  All three use the same `.tb-card` tokens and kind stripes. The kind line now reads
  `· pinned` on pinned cards.
- **`board/BoardHead.tsx`** has the `Map / Focus / Outline` tabs and the shared head:
  tabs, the view's own controls, and the kind legend. Map is the default.
- **`board/FocusView.tsx`**:
  - **Layout.** The selected card sits centred and large. Parents are above, children
    below, jumps in a column to the right, each tier with the prototype's mono label and
    count. It's a CSS grid instead of the prototype's absolute positioning, so jumps
    never overlap the centre. Below 760px of container width (container query) the tiers
    stack.
  - **Lines.** Bezier lines run from the centre's edge to each neighbour's facing edge,
    measured from the DOM after layout and re-measured by a `ResizeObserver`. Hovering or
    focusing a neighbour turns its line and border accent.
  - **Clicking a neighbour** selects it, which re-centres and sends the selection to
    the channel.
  - **Trail.** The bottom bar shows past centres. Clicking one goes back to it and
    truncates the trail there. Each card appears once, newest last, at most 8.
  - **Pins** show on the right of the same bar, and clicking a pin re-centres.
  - **Empty state.** It invites you to select a card or pick a pin.
- **`board/OutlineView.tsx`**:
  - **Groups.** Ideas, questions, decisions, objections, sources, in that order, with
    counts. Empty kinds are skipped.
  - **Rows.** The title is struck through when resolved and tagged `pinned` when
    pinned. Outgoing links are listed as `type → title`, and clicking a link target
    selects that card. The creator is on the right.
  - **Selecting.** Click selects the card. Shift or cmd click adds or removes it, as on
    the map. Enter or Space works too.
  - **Archived cards** don't appear. They're already dropped from board state, and
    `outlineGroups` filters `archived` as well.
- **`App.tsx`** owns the view, the Focus state `{id, trail}` (client only) and the Map
  viewport:
  - **Shared selection.** It's shared by all three views and still goes to the channel.
    The Focus centre is the most recently selected card.
  - **When moves reach the trail.** Only centre changes made while Focus is open (a
    neighbour, a pin, a link in the inspector) push onto the trail. Selecting in Map or
    Outline just sets the centre, as in the prototype.
  - **Opening Focus with nothing selected** re-selects the last centre, or the first
    pin, so the centre and what the AI sees agree.
  - **Map viewport.** Views unmount when you leave them, so App keeps the Map's
    viewport. Coming back restores your pan and zoom instead of re-fitting.
- **Inspector**: a **Pin / Unpin** toggle beside Edit and Resolve (`aria-pressed`,
  accent when pinned), and `· pinned` in the kind line. The feed describes pin events as
  `pinned “X”` / `unpinned “X”`, and tool calls as `update_card … pinned=true`.

### Bug found and fixed in the Map during verification

The browser check crashed the whole page ("Maximum update depth exceeded") when switching
to Map with a card already selected. That can't happen in Phase 3, where Map is always
mounted first with nothing selected.

- **Cause.** `MapView` wrote React Flow's `onSelectionChange` back into the app
  selection. React Flow fires that callback whenever the `nodes` prop syncs into its
  store, and on mount it fires first with an empty store. The empty report and the
  `selected` props then chased each other forever.
- **Fix.** Selection now flows one way. The user's picks come from `select` changes in
  `onNodesChange`, which React Flow emits for click, shift or cmd click, box select and
  pane click, but not for prop syncs. `onSelectionChange` is gone.
- **Also.** The first nodes are built in `useState`'s initializer, so the first render
  already carries the selection.
- **Re-checked afterwards:** map click select, shift-click multi-select and pane-click
  deselect.

## Decisions the plan did not cover

1. **"A Graph action" for pins is `Card.update` accepting `pinned`**, not a separate
   `:pin` action. It keeps `update_card` to one write and one event even when pinned is
   combined with other fields, and the existing Phase 2/3 invariants hold unchanged.
2. **Neighbour order** follows link order, and a card linked twice in a tier shows once
   with both labels, e.g. `answers → · resolves →`. A card can sit in two tiers when its
   links say so (a parent that it also cites).
3. **The trail only grows from moves made inside Focus** (prototype behaviour), dedupes
   (a revisited card moves to the end, and the current centre is never in it), keeps 8,
   and going back truncates rather than pushing.
4. **The Focus centre follows the most recent selection** in every view, and opening Focus
   with nothing selected re-selects the last centre or first pin. Centre and selection
   never disagree, so what you see centred is what `read_selection` returns.
5. **Views unmount** when not shown. The Map keeps its viewport through App state.
   `RegionForm` in the inspector falls back to a 120px card height when the map isn't
   mounted, since it can't measure nodes then.
6. **Prototype's absolute Plex layout became a grid** so tiers can't overlap the centre
   (the prototype's jumps column covers the centre at this width). The look is the same:
   tier labels, 200px neighbour cards, accent-ringed centre, trail and pin chips.
7. **Outline link targets are clickable** (select the target) in addition to the row.
8. **Map selection now comes from `onNodesChange`**, not `onSelectionChange` (see the bug
   above). This changes Phase 3 code, but it's needed for the Phase 4 tabs to work.

## Commands

```sh
docker compose up -d --wait
mix setup                 # or: mix ash.migrate (new cards.pinned column)
mix phx.server            # board at http://localhost:4000 — Map / Focus / Outline tabs
mix precommit             # now includes assets.test (vitest)
mix assets.test           # just the TypeScript unit tests

# Pin a card from the MCP side and watch the pins strip update live
curl -s localhost:4000/mcp -H 'content-type: application/json' \
  -H 'accept: application/json, text/event-stream' \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/call","params":{"name":"update_card","arguments":{"input":{"id":"<card id>","pinned":true}}}}'
```
